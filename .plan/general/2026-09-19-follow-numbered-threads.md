# 연속글 상세 수집과 일시 연결 끊김 복구

- Date: 2026-09-19
- Jira: None
- Status: In progress

## Goal

프로필 여러 게시물을 수집하는 중 1/n 연속글을 발견하면 상세 화면을 열어 같은 작성자의 1..n 본문을 저장하고 프로필 탐색으로 돌아온다. 사용자 제공 12편 표본과 합성 20편으로 검증하며, 누락 번호가 있으면 완료로 표시하지 않는다. 일시 ping 실패만으로 수집을 영구 중단하는 결함도 수정한다.

## Non-goals

전체 이력 완전성을 보장하거나 비공개 API·쿠키를 이용하지 않는다. 다른 작성자의 댓글을 해당 연속글로 묶지 않으며 보안 화면을 자동 통과하지 않는다.

## Context / Constraints

사용자가 0.3.0 설치·작동을 확인했고 35회 부근 중단, 용어 혼동, 3/n 이후 누락을 보고했다. 기존 초안 PR #2를 같은 작업 브랜치에서 보완한다. 파일 10개의 수정 전 백업을 압축 해제해 SHA-256을 대조했다.

실제 DOM: 프로필에서 1/12·2/12만 보이던 글이 상세 클릭 후 1/12..12/12 전부 로딩됨. 상세 루트는 다른 본문 레이아웃이고, 이전 목록이 숨겨진 DOM으로 남을 수 있음. 최근 표본과 사용자 제공 `@jingammmm/post/DdVi5vwCdyh`를 대조한다. ping 예외 한 번 뒤 DB running=false가 되어 정상 snapshot까지 거절되는 경로를 재현했다. Chrome 메모리 최적화가 직접 원인인지는 미확정이다.

## Approach (Checklist)

- [x] **Step 0: Recon** — 사용자 현상·오류 문구, 실제 상세 UI, 저장·제어 계약, 원격 상태 확인.
- [x] **Step 1: Implementation** — 프로필→상세→복귀 상태를 저장하고 작성자·루트·번호별 완성도를 검증. 수집기 연결 복구와 숨은 탭 대기. 저장 지표를 쉬운 말로 변경.
- [x] **Step 2: Tests** — 90개 자동 시험 통과. 상세 12/20편·누락·타인 댓글·복귀 후 다음 게시물, 기존 DB 업그레이드, 일시 ping 실패/수동 중단/탭 복구 시험. 실제 12편 두 묶음의 본문 24개를 표시 원문과 대조해 일치.
- [x] **Step 3a: Package** — 설치 경로를 유지한 0.4.0 파일 업데이트와 별도 ZIP 제공. 소스·압축 해제본·설치 폴더의 11개 파일 해시 일치. 기존 초안 PR #2에 반영한다.
- [ ] **Step 3b: Installed validation** — 사용자에게 확장·Threads 탭 새로고침 후 계정 화면에서 시작을 요청했다. 설치된 0.4.0의 연속 탐색·다운로드 검증은 대기 중이다.

## Validation

- **Commands to run:** `npm test`, `npm run test:extension`, `git diff --check`, JS 구문 검사, 패키지 압축 해제 후 해시 비교.
- **Expected output:** 12/12·20/20 번호별 본문 보존, 누락 시 missing 경고, 다른 작성자 제외, 목록 복귀 후 수집 지속. 첫 ping 실패 후 정상 snapshot을 계속 수용.
- 실제 DOM/수집기 모듈 시험과 Chrome 설치 후 전체 실행은 구분한다. Chrome 관리 화면은 도구 URL 정책상 직접 열 수 없다.

## Risks & Rollback

- **Risks:** 상세 페이지 레이아웃 변화, 삭제된 중간 글, 지연 로딩, 확장 권한 상실, 브라우저 종료. 권한을 늘리지 않고 사용자 실행 탭 안에서만 처리한다.
- **Rollback steps:** 이전 파일 백업은 보존하되 DB 업그레이드 후에는 0.3.0 파일만 복원하지 않는다(DB 버전 오류 가능). 문제 시 중지·내보내기 후 DB 스키마 2를 유지한 수정판을 적용한다. 업그레이드는 새 store 추가만 하며 기존 글을 삭제하지 않는다. 기존 설치 폴더를 유지해 확장 ID 변경에 따른 데이터 분리를 피한다.

## Open Questions

사용자 종료 메시지는 연결 단절 경로와 일치하지만 실제 탭 discard/freeze 여부는 확정되지 않았다. 0.4.0에는 연결 상태와 명확한 중단 사유를 남긴다.
