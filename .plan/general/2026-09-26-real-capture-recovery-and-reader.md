# 실제 미완료 자료 복구·재개 속도·읽기 문서

## 관측 근거

사용자가 저장한 내보내기 두 파일을 읽기 전용으로 비교했다. 1,282개/미완료 21묶음에서 1,305개/미완료 17묶음으로 변했다. 남은 17묶음은 번호 관계 충돌이 없고 미확보 번호 20개는 이미 카드로 저장되어 있다. 그중 13개는 과거 본문·번호 null 판독 실패 기록, 3개는 첨부 구조 경고, 4개는 순번 표식 경고다. 사용자 본문·브라우저 상태는 저장소에 넣지 않는다.

실제 두 편 글은 현재 본문·번호가 정상 구조이지만, 이전 본문·번호가 동시에 null인 기록은 정상 판독 결과로 보강되지 않는 저장 규칙을 재현했다. 순번 경고 사례의 실제 화면에서는 본문의 계정 언급이 서비스 순번과 같은 외부 클래스를 사용함을 확인했다.

실제 reader·storage·content를 사용하는 가상 시계 시험에서, 긴 글을 스크롤해도 DOM이 같거나 누적 묶음·사진 메모가 현재 부분 화면보다 많으면 0.5초 가속이 꺼짐을 재현했다. 신규·변경 본문은 기본 속도를 유지해야 한다.

## 구현·검증 경계

1. 기존 미확인 null 본문과 null 번호를 현재 정상 본문·번호로 복구한다. 날짜·계정·본문·첨부의 실제 충돌은 덮어쓰지 않는다. 실제 저장소와 연속글 완료까지 회귀 시험한다.
2. 실제 관측한 계정 언급 구조를 숫자 순번과 구분하고 본문을 보존한다. 미지원 구조와 충돌은 경고한다. 나머지 첨부 사례도 실제 DOM에서 확인한 범위만 처리한다.
3. 동일한 정상 본문을 실제로 스크롤하는 경우와 멈춘 스크롤을 구분한다. 현재 부분 화면과 누적 자료는 정상 병합 결과로 비교한다. 저장 응답 이전 이동 금지, 새 글·오류·로딩의 기본 간격을 유지한다.
4. 읽기용 오프라인 HTML을 추가한다. 본문 중심의 한 열 문서에서 확인된 연속글만 번호순 한 묶음으로 읽는다. 모든 카드·긴 첨부를 보존하고 미확보 번호와 연결 미확인 글을 구분한다. 사용자에게 형식 선택을 질문했고 별도 응답 전 기본안은 HTML 추가와 기존 Markdown 유지다.
5. 기존 공개 경계(reader 판독, 병합·저장, content 스크롤, export 문서, popup 버튼)에서 실패 재현 후 수정한다. 실제 자료는 로컬 진단·문서 생성에만 사용하고 회귀 자료는 합성으로 만든다.
6. 전체 시험·독립 검토·패키지 해시 검증·PR 반영을 수행한다. 설치 파일 교체와 Chrome 재로드·실제 실행 확인을 분리해 보고한다. 기존 기록은 초기화하지 않는다.

## 한계

일반 목록은 Threads가 순서대로 로드하는 범위에서 진행한다. 임의 날짜 위치로 즉시 이동하거나 화면에 나오지 않은 본문을 추측하지 않는다. 기존 오류 기록 중 실제 충돌·미지원 구조는 경고로 남기며, 새 재수집을 실행하기 전에는 저장된 자료가 자동 완성됐다고 주장하지 않는다.
