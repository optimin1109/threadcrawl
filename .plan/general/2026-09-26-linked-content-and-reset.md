# 읽을 수 있는 연속글 본문 누락과 계정별 초기화

## 확인한 문제

- 사용자가 제공한 정확한 두 상세 페이지를 별도 탭에서 읽었다. 첫 편에는 `이용할 수 없는 게시물` 표시가, 다른 두 편에는 외부 뉴스 미리보기가 있다. 각 작성자 본문과 순번은 정상 구조이며 중첩 게시물은 없다.
- reader가 지원하지 않는 본문 뒤 구조를 오류로 남기고, 완료 검증이 이 오류를 포함한 본문을 제외한다. 따라서 화면에 보이는 번호까지 미확보로 표시하며 상세를 방문한다.
- 팝업에는 누적·중지·내보내기만 있어 문제가 있던 계정을 처음부터 수집할 수 없다.

## 구현

1. 확인된 안내와 외부 미리보기 구조만 익명 자료로 재현해 reader 회귀 시험을 먼저 실패시킨다. 작성자 본문을 보존하고 안내·미리보기는 별도 note로 기록한다. 미확인 구조와 실제 순번 충돌은 계속 완료를 막는다.
2. Markdown에 이용 불가 원문 및 외부 기사 전문·이미지의 미저장 사실을 표시한다. 미리보기 주소에서 Threads 추적 매개변수를 제거하고 위험한 URL과 출력 주입을 차단한다.
3. 같은 프로필 묶음에서 두 편 모두 읽히면 상세를 열지 않는 통합 시험과 기존 저장 오류의 재수집 복구를 검증한다.
4. 중지된 마지막 수집 계정만 초기화하는 버튼을 추가한다. 계정명과 범위 확인 후 관련 저장소를 한 트랜잭션으로 삭제하며 다른 계정·내보낸 파일은 보존한다. 이전 실행의 늦은 메시지와 대상 변경을 거절한다. 실제 사용자 자료는 삭제하지 않는다.
5. 전체 시험·구문·diff·독립 검토 후 0.4.4를 포장한다. 설치 경로 갱신은 수집 중지를 확인한 뒤 기존 파일 백업과 해시 검증을 거친다.
6. 기존 작업 브랜치에 커밋·push하고 draft PR을 갱신한다. 설치된 확장의 재로드와 실제 자동 수집 성공은 별도 검증으로 남긴다.

## 경계

외부 기사에 접근하거나 전문을 수집하지 않는다. 일반 인용·미확인 첨부 전체를 허용하지 않는다. 실제 게시물 원문, CDN 주소 및 추적 토큰은 커밋하지 않는다. 확장 관리 화면은 브라우저 정책상 조작할 수 없어 사용자가 재로드해야 한다.
