# Threads 텍스트 보관 0.4.0

현재 Chrome에서 보고 있는 공개 Threads 프로필의 본문·긴 텍스트 첨부·번호가 붙은 연속글을 저장합니다. 확장 버튼을 눌러 직접 시작하며, 추가 로그인·API 키·외부 수집 서비스는 필요하지 않습니다.

## 0.3에서 업데이트할 때

먼저 수집을 중지하고 JSON을 내보내세요. 기존에 설치한 `deliverables/threads-text-archive-0.3.0` 폴더를 그대로 갱신한 뒤 `chrome://extensions`에서 해당 확장의 **새로고침** 버튼을 누릅니다. 폴더 이름은 그대로여도 확장 버전은 0.4.0입니다. Threads 탭도 새로고침한 뒤 수집을 다시 시작하세요.

**확장을 삭제하거나 다른 폴더에서 새로 설치하지 마세요.** 기존 폴더와 확장 ID를 유지해야 저장 자료를 이어 쓸 수 있습니다. 0.4는 기존 IndexedDB 자료를 유지하면서 연속글 정보를 추가합니다.

## 설치와 실행

1. Chrome 주소창에 `chrome://extensions`를 입력합니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누르고 이 `manifest.json`이 들어 있는 폴더를 선택합니다. ZIP 파일 자체를 선택하지 않습니다.
4. `https://www.threads.com/@hongso0921`을 엽니다. 기존에 열려 있던 탭은 새로고침합니다.
5. Chrome의 확장 메뉴에서 **Threads 텍스트 보관 — 실험판**을 열고 **이 계정 수집 시작 / 계속 누적**을 누릅니다.
6. 필요한 만큼 진행한 뒤 **중지**, **읽을 문서 저장 (Markdown)**을 누릅니다. 재가공용 자료는 **원본 자료 저장 (JSON v2)**로 함께 저장합니다.

팝업은 닫아도 됩니다. **수집하는 Threads 탭을 화면 앞에 두세요.** 다른 탭으로 옮기면 수집과 스크롤을 기다립니다. 자동 탐색은 대기 시간을 포함해 최대 45분 또는 1,800회입니다. 프로필에서 30초간 새 글이 나타나지 않으면 중단하며, 이는 전체 수집 완료를 뜻하지 않습니다. 로그인·보안 안내가 나타나면 멈춥니다.

## 연속글과 진행 표시

- 프로필을 읽다가 `1/12` 같은 연속글 시작을 찾으면 같은 탭에서 상세 페이지를 엽니다. 후속 번호를 확인한 뒤 프로필의 저장한 위치로 돌아와 다음 글을 탐색합니다.
- 모든 번호의 글이 저장되고 번호 충돌이 없어야 해당 연속글을 완료로 표시합니다. 찾지 못한 번호는 **불완전** 상태와 누락 번호로 남깁니다. 게시물 원문은 각각 보존합니다.
- **저장된 글**은 게시물 ID별 개수입니다. 같은 화면·글을 여러 번 확인한 횟수는 저장된 글이 중복으로 늘었다는 뜻이 아닙니다.
- 표시되는 작성일 범위는 저장한 글의 가장 오래된 날짜와 가장 최근 날짜입니다. 고정 글도 포함하므로 그 사이의 모든 글을 확보했다는 뜻이 아닙니다.

## 저장과 계속 누적

- 확인한 글은 계정별 IndexedDB에 저장하며, 화면을 넘기기 전에 저장 확정을 기다립니다.
- 일시적인 연결 실패는 즉시 종료로 처리하지 않습니다. 탭이 다시 활성화되거나 로딩을 마치면 허용된 프로필·진행 중 상세 페이지에서 저장한 진행 정보를 바탕으로 복구를 시도합니다. 복구 횟수와 실행 시간에는 상한이 있습니다.
- 탭을 닫아도 이미 확정한 글은 남습니다. 탭을 다시 열고 수집을 직접 시작하세요. 수동 중지·보안 안내·시간 상한으로 끝난 수집은 자동 재시작하지 않습니다. 직접 다시 시작하면 현재 화면부터 기존 게시물 ID와 대조해 누적합니다.
- 뒤늦게 나타난 긴 첨부는 기존 글에 보강합니다. 내용이 충돌하면 최초 내용을 보존하고 경고를 남깁니다.
- JSON/Markdown은 마지막으로 시작한 계정의 자료입니다. 다른 계정 자료를 다시 내보내려면 해당 계정에서 시작 후 중지하세요.
- 확장 삭제나 브라우저 프로필 삭제 전에 파일로 내보내세요. 이전 실험판의 `chrome.storage` 데이터는 건드리지 않으며 자동 이전하지 않습니다. 0.4의 DB 갱신 후에는 0.3 실행 파일만 되돌려 저장 자료를 읽는 방법을 보장하지 않습니다.

Markdown은 읽을 문서로, 원문 줄바꿈과 공백을 보존하는 텍스트 블록을 사용합니다. JSON v2는 게시물·첨부·연속글 상태를 재가공하거나 확인할 자료입니다. 기존 데스크톱의 v1 가져오기와 호환되지 않습니다. 두 형식 모두 확인하지 못한 전체 과거 글을 포함하는 백업은 아닙니다.

## 확인된 범위와 한계

2026-09-19 실제 `@hongso0921` 프로필 DOM에서 소개글 66자와 긴 첨부 7,835자(줄바꿈 62개)를 분리했고, 첨부는 펼친 원문과 정확히 일치했습니다. 사용자는 설치한 0.3의 실행을 확인했으며, 도중 중단과 연속글 누락을 보고했습니다.

후속 조사에서는 실제 상세 페이지 두 곳의 12개 연속글을 각각 확인했습니다. 0.4 reader와 같은 본문 읽기 로직을 읽기 전용으로 실행해 번호·본문 24개를 추출했고, 서비스 배지를 제외한 페이지 문단과 공백·줄바꿈까지 일치했습니다. 확장을 설치해 실행한 검증은 아니며, **설치된 0.4의 시작·상세 이동·복귀·저장·다운로드 검증은 아직 남아 있습니다.**

전체 과거 글, 숨겨진 추가 답글, 인용·중첩 글, 미디어 전용 글은 완전 수집을 보장하지 않습니다. 모르는 구조는 해당 게시물 링크와 경고를 남깁니다.

## 권한과 검증

권한은 `activeTab`, `scripting`, `storage`입니다. 사용자가 실행한 탭의 DOM만 읽으며 쿠키·비공개 API·외부 서버 전송을 사용하지 않습니다.

개발 검증: 저장소 루트에서 `npm ci`, `npm test`, `npm run test:extension`. 설치 자체에는 Node나 npm이 필요 없습니다. 0.4 구현 후 로컬 시험 90개가 통과했습니다. 긴 첨부·연속글 상태·저장 보존·연결 복구·오래된 실행 차단·Markdown 보존 등을 확인한 결과이며, 실제 Chrome 설치 검증과는 구분합니다.
