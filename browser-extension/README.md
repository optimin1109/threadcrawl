# Threads 텍스트 보관 0.4.5

현재 Chrome에서 보고 있는 공개 Threads 프로필의 본문·긴 텍스트 첨부·번호가 붙은 연속글을 저장합니다. 확장 버튼을 눌러 직접 시작하며, 추가 로그인·API 키·외부 수집 서비스는 필요하지 않습니다.

## 기존 설치에서 업데이트할 때

먼저 수집을 중지하고 JSON을 내보내세요. 기존에 설치한 `deliverables/threads-text-archive-0.3.0` 폴더를 그대로 갱신한 뒤 `chrome://extensions`에서 해당 확장의 **새로고침** 버튼을 누릅니다. 폴더 이름은 그대로여도 확장 버전은 0.4.5입니다. 팝업 제목 옆에서도 버전을 확인할 수 있습니다. Threads 탭도 새로고침한 뒤 수집을 다시 시작하세요.

**확장을 삭제하거나 다른 폴더에서 새로 설치하지 마세요.** 기존 폴더와 확장 ID를 유지해야 저장 자료를 이어 쓸 수 있습니다. 0.4는 기존 IndexedDB 자료를 유지하면서 연속글 정보를 추가합니다.

## 설치와 실행

1. Chrome 주소창에 `chrome://extensions`를 입력합니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누르고 이 `manifest.json`이 들어 있는 폴더를 선택합니다. ZIP 파일 자체를 선택하지 않습니다.
4. `https://www.threads.com/@hongso0921`을 엽니다. 기존에 열려 있던 탭은 새로고침합니다.
5. Chrome의 확장 메뉴에서 **Threads 텍스트 보관 — 실험판**을 열고 **이 계정 수집 시작** 또는 **이 계정 수집 계속하기**를 누릅니다.
6. 필요한 만큼 진행한 뒤 **중지**, **읽을 문서 저장 (Markdown)**을 누릅니다. 재가공용 자료는 **원본 자료 저장 (JSON v2)**로 함께 저장합니다.

팝업은 닫아도 됩니다. **수집하는 Threads 탭을 화면 앞에 두세요.** 다른 탭으로 옮기면 수집과 스크롤을 기다립니다. 자동 탐색은 대기 시간을 포함해 최대 45분 또는 1,800회입니다. 프로필에서 30초간 새 글이 나타나지 않으면 중단하며, 이는 전체 수집 완료를 뜻하지 않습니다. 로그인·보안 안내가 나타나면 멈춥니다.

## 연속글과 진행 표시

- 프로필 목록의 같은 묶음에서 `1/2`·`2/2`처럼 모든 번호를 읽었으면 상세를 열지 않고 다음 글로 넘어갑니다. 사진만 있는 번호 글도 같은 게시물의 사진임을 확인하면 본문이 빈 미디어 편으로 기록합니다. 사진 링크뿐 아니라 확인된 여러 장 사진 버튼 구조도 지원합니다. 옆에 있다는 이유만으로 다른 묶음의 글을 합치지 않습니다.
- 첫 확인에서 번호가 빠졌으면 프로필을 한 번 더 스크롤하고 1.5초의 렌더링 여유를 둔 뒤 다시 판정합니다. 그 사이 모두 확인되면 상세에 들어가지 않습니다. 원래 글의 링크가 사라졌으면 불완전으로 기록하고 다음 글을 계속 확인합니다.
- 목록에서 후속 번호가 빠진 `1/12` 같은 글은 같은 탭에서 상세 페이지를 엽니다. 확인한 뒤 프로필의 저장한 위치로 돌아옵니다. 상세에서는 번호의 진전이 10초간 없거나 탐색이 120초를 넘으면 누락을 기록하고 돌아옵니다. 화면 변화나 답글 펼치기가 이 검사를 미루지 않습니다.
- 모든 번호의 글이 저장되고 번호 충돌이 없어야 해당 연속글을 완료로 표시합니다. 찾지 못한 번호는 **불완전** 상태와 누락 번호로 남깁니다. 게시물 원문은 각각 보존합니다.
- **저장된 글**은 게시물 ID별 개수입니다. 같은 화면·글을 여러 번 확인한 횟수는 저장된 글이 중복으로 늘었다는 뜻이 아닙니다.
- 표시되는 작성일 범위는 저장한 글의 가장 오래된 날짜와 가장 최근 날짜입니다. 고정 글도 포함하므로 그 사이의 모든 글을 확보했다는 뜻이 아닙니다.
- 확인된 사진 첨부와 장소 태그는 본문 읽기 실패로 취급하지 않습니다. 사진 원본·사진 속 글자는 저장하지 않으며 그 사실과 사진 링크를 문서에 표시합니다. 장소 태그는 별도로 보존합니다. 알 수 없는 첨부 구조는 계속 경고합니다.
- 확인된 뉴스 링크 미리보기나 **이용할 수 없는 게시물** 안내가 있어도 작성자 본문과 번호는 저장합니다. 미리보기 제목·표시 도메인·외부 주소, 이용 불가 안내는 본문과 별도로 남깁니다. 외부 기사 전문·미리보기 이미지·이용 불가 인용 원문은 저장하지 않습니다. 이 때문에 읽을 수 있는 번호 본문을 미확보로 계산하지 않습니다.

## 미완료 글만 보완하려면

1. 수집을 **중지**하고, 팝업에 표시된 계정의 프로필 또는 해당 계정의 글을 같은 탭에서 엽니다.
2. **미완료 글만 다시 수집**을 누릅니다. 저장된 미완료 묶음의 첫 글 주소로 직접 이동하므로 과거 종료 지점까지 프로필을 내릴 필요가 없습니다. 기존 글과 완료된 묶음은 보존합니다.
3. `현재/전체 묶음` 진행과 남은 번호를 확인합니다. 확인 가능한 본문을 보강하고 저장이 확정되면 다음 미완료 주소로 이동합니다. 한 묶음에서 10초간 새 번호가 없거나 120초를 넘기면 남은 번호를 기록하고 넘어갑니다.
4. 한 차례 확인이 끝나면 해당 프로필로 돌아와 멈춥니다. 이후 더 오래된 글을 찾으려면 **이 계정 수집 계속하기**를 누릅니다. 직접 재수집은 일반 프로필 수집을 자동 시작하지 않습니다.

페이지 이동 실패·대상 이탈·로그인·보안 안내는 재수집을 중단합니다. 삭제·접근 제한·미지원 구조나 번호 충돌은 다시 방문해도 미완료로 남을 수 있습니다. 이 작업에 **초기화는 필요하지 않습니다.**

## 이 계정을 처음부터 다시 수집하려면

1. **중지**를 누릅니다. 기존 자료가 필요하면 **원본 자료 저장 (JSON v2)**으로 먼저 보관합니다.
2. **@계정 수집 기록 초기화**에 표시된 계정명을 확인하고 누릅니다.
3. 삭제 범위를 안내하는 확인창에서 초기화를 확인합니다. 해당 계정의 저장 글·연속글·오류·진행 기록을 지우며 되돌릴 수 없습니다. 다른 계정 기록과 이미 내려받은 파일은 남습니다.
4. 해당 계정 프로필의 맨 위로 이동한 뒤 **이 계정 수집 시작**을 누릅니다. 초기화만으로 수집이 자동 시작되지는 않습니다.

초기화 대상은 팝업에 표시된 마지막 수집 계정입니다. 실행 중에는 초기화할 수 없으며, 확인 사이 다른 수집이 시작되면 삭제를 거절합니다.

## 저장과 계속 누적

- 확인한 글은 계정별 IndexedDB에 저장하며, 화면을 넘기기 전에 저장 확정을 기다립니다.
- 일시적인 연결 실패는 즉시 종료로 처리하지 않습니다. 탭이 다시 활성화되거나 로딩을 마치면 허용된 프로필·진행 중 상세 페이지에서 저장한 진행 정보를 바탕으로 복구를 시도합니다. 복구 횟수와 실행 시간에는 상한이 있습니다.
- 탭을 닫아도 이미 확정한 글은 남습니다. 탭을 다시 열고 수집을 직접 시작하세요. 수동 중지·보안 안내·시간 상한으로 끝난 수집은 자동 재시작하지 않습니다. 직접 다시 시작하면 현재 화면부터 기존 게시물 ID와 대조해 누적합니다.
- 계속하기는 과거 스크롤 위치를 즉시 복원하지 않습니다. 다만 새로 표시된 화면 전체가 저장된 정상 글과 같다는 저장 응답을 받으면 스크롤 간격을 1.5초에서 0.5초로 줄입니다. 매 화면 읽기·저장 확인과 화면 높이 65%의 겹치는 이동 폭은 유지하며, 새 글·로딩·미확인 본문·해결 중인 묶음·스크롤 뒤 그대로인 화면에서는 기본 간격을 사용합니다. 실제 소요 시간은 Threads 로딩 속도에 따라 달라집니다.
- 뒤늦게 나타난 긴 첨부는 기존 글에 보강합니다. 내용이 충돌하면 최초 내용을 보존하고 경고를 남깁니다.
- JSON/Markdown은 마지막으로 시작한 계정의 자료입니다. 다른 계정 자료를 다시 내보내려면 해당 계정에서 시작 후 중지하세요.
- 확장 삭제나 브라우저 프로필 삭제 전에 파일로 내보내세요. 이전 실험판의 `chrome.storage` 데이터는 건드리지 않으며 자동 이전하지 않습니다. 0.4의 DB 갱신 후에는 0.3 실행 파일만 되돌려 저장 자료를 읽는 방법을 보장하지 않습니다.

Markdown은 읽을 문서로, 원문 줄바꿈과 공백을 보존하는 텍스트 블록을 사용합니다. JSON v2는 게시물·첨부·연속글 상태를 재가공하거나 확인할 자료입니다. 기존 데스크톱의 v1 가져오기와 호환되지 않습니다. 두 형식 모두 확인하지 못한 전체 과거 글을 포함하는 백업은 아닙니다.

## 확인된 범위와 한계

2026-09-19 실제 `@hongso0921` 프로필 DOM에서 소개글 66자와 긴 첨부 7,835자(줄바꿈 62개)를 분리했고, 첨부는 펼친 원문과 정확히 일치했습니다. 사용자는 설치한 0.3의 실행을 확인했으며, 도중 중단과 연속글 누락을 보고했습니다.

후속 조사에서는 실제 상세 페이지 두 곳의 12개 연속글을 각각 확인했습니다. 0.4 reader와 같은 본문 읽기 로직을 읽기 전용으로 실행해 번호·본문 24개를 추출했고, 서비스 배지를 제외한 페이지 문단과 공백·줄바꿈까지 일치했습니다. 확장을 설치해 실행한 검증은 아니며, **설치된 0.4의 시작·상세 이동·복귀·저장·다운로드 검증은 아직 남아 있습니다.**

전체 과거 글, 숨겨진 추가 답글, 인용·중첩 글, 미디어 전용 글은 완전 수집을 보장하지 않습니다. 모르는 구조는 해당 게시물 링크와 경고를 남깁니다.

0.4.1에서는 사용자 제보의 사진 포함 2편 글을 실제 목록에서 다시 읽어 31자·98자 본문과 순번, 같은 묶음을 확인했습니다. 두 본문은 표시 문단과 일치했습니다. 0.4.2에서는 `1/2`에 글과 사진, `2/2`에 사진만 있는 묶음을 회귀 시험으로 재현해 프로필에서 완료하고 상세를 열지 않는 동작을 확인했습니다. 실제 DOM 판독과 설치된 0.4.2의 자동 탐색 실행 검증은 별개입니다.

## 권한과 검증

권한은 `activeTab`, `scripting`, `storage`입니다. 사용자가 실행한 탭의 DOM만 읽으며 쿠키·비공개 API·외부 서버 전송을 사용하지 않습니다.

0.4.3은 실제 프로필과 상세에서 확인한 링크 없는 사진 버튼 구조를 추가로 처리하고, 상세 진입 전에 프로필의 후속 편을 한 번 더 확인합니다. 저장 완료 순간 화면이 바뀌어도 완료한 글의 이전 상세 대기는 제거합니다. 사용자가 보고한 정확한 중단 글은 특정하지 못했으며, 설치된 0.4.3의 재수집 성공은 아직 확인하지 않았습니다.

0.4.4는 실제 제보 페이지의 이용 불가 안내와 이미지 유무가 다른 두 외부 미리보기 구조를 추가로 처리합니다. 같은 계정을 다시 관측하면 기존 첨부 경고가 있던 본문도 보강합니다. 계정별 초기화 버튼을 추가했으며 실제 사용자 자료를 대신 삭제하지 않았습니다.

0.4.5는 미완료 주소 직접 재수집과 저장 구간의 짧은 스크롤 대기를 추가합니다. 저장소가 미확보로 판정한 번호는 과거 멤버 기록만으로 완료로 계산하지 않고, 정상 본문을 다시 읽어야 보완합니다. 권한·DB 버전과 기존 자료는 유지합니다.

개발 검증: 저장소 루트에서 `npm ci`, `npm test`, `npm run test:extension`. 설치 자체에는 Node나 npm이 필요 없습니다. 확장 전용 시험은 전체 시험에 포함됩니다. 최신 검사 결과와 실제 Chrome 검증 범위는 `docs/chrome-extension-0.4.5-validation.md`에 기록합니다. 합성 DOM 시험과 실제 설치 실행은 구분합니다.
