# Threads 공개 계정 텍스트 보관 프로그램 요구사항

## 1. 목적

사용자가 지정한 Meta Threads 공개 계정의 게시물을 개인 열람용으로 한 번에 백업한다.

수집 결과는 계정별 Markdown 파일 하나로 저장하며, 이미지와 동영상은 저장하지 않는다.

## 2. 대상과 사용 규모

- 대상 서비스: Meta Threads
- 대상 계정: 사용자가 정상적으로 열람할 수 있는 공개 계정
- 예상 대상 수: 약 5~10개
- 실행 단위: 한 번에 계정 하나
- 예상 게시 빈도: 주 2~3개부터 하루 1개 이상
- 예상 게시 기간: 주로 1~2년
- 사용 목적: 개인적인 로컬 아카이빙
- 실행 환경: Windows, Chrome 사용

## 3. 수집 대상

### 3.1 일반 게시물

- 대상 계정이 작성한 원글의 본문을 수집한다.
- 작성 날짜를 함께 수집한다.
- 본문의 원래 줄바꿈, 이모지, 특수문자를 가능한 한 그대로 보존한다.
- 본문 안에 작성자가 넣은 외부 웹 주소는 그대로 보존한다.
- 이미지나 영상이 첨부되어 있어도 본문 텍스트가 있으면 텍스트는 수집한다.
- 긴 텍스트 첨부물이 있으면 펼쳐서 전문을 수집한다.

### 3.2 한꺼번에 작성된 게시물 묶음

- Threads 작성 화면에서 처음부터 `1/N`부터 `N/N`까지 한꺼번에 만든 묶음은 하나의 논리적 게시물로 합친다.
- Threads가 실제로 제공하는 묶음 관계 또는 순서 정보로 확인된 경우에만 묶음으로 처리한다.
- 화면에 실제 `1/3`, `2/3`, `3/3` 등의 순서가 제공되면 그 표시를 그대로 사용할 수 있다.
- 프로그램이 순번이나 전체 개수를 추측하여 새로 만들면 안 된다.

### 3.3 제외할 답글

- 최초 게시 후 작성자가 자기 원글에 나중에 추가한 답글은 제외한다.
- 작성자가 자기 글 아래 여러 갈래로 추가한 답글도 제외한다.
- 대상 계정이 다른 사람의 게시물이나 댓글에 작성한 답글은 제외한다.
- 다른 사용자가 대상 계정의 글에 작성한 모든 답글과 댓글을 제외한다.

### 3.4 리포스트

- 대상 계정이 단순 리포스트한 게시물도 보관한다.
- 리포스트된 원글 한 개의 본문만 수집한다.
- 리포스트 원문의 작성자가 이어 쓴 연속글은 따라가지 않는다.
- 결과에서 일반 게시물과 구별되도록 `**리포스트**`라고 표시한다.
- 리포스트된 원글이 이미지나 영상만 포함하고 텍스트가 없다면 제외한다.

### 3.5 인용 게시물

- 대상 계정이 다른 게시물을 인용하며 작성한 경우 대상 계정이 덧붙인 본문만 수집한다.
- 인용된 원문의 본문은 수집하지 않는다.
- 대상 계정이 덧붙인 텍스트가 전혀 없다면 제외한다.

### 3.6 텍스트가 없는 게시물

- 이미지, 영상 또는 기타 미디어만 있고 본문 텍스트가 전혀 없는 게시물은 완전히 제외한다.
- 제외 표시나 빈 항목도 Markdown 파일에 남기지 않는다.

## 4. 수집하지 않는 정보

- 이미지, GIF, 음성 및 동영상 파일
- 미디어 URL
- Threads 게시물 원본 URL
- 좋아요, 답글, 리포스트, 인용 및 조회 수
- 게시물 수정 이력
- 삭제 추적 정보
- 다른 사용자의 댓글과 답글
- 작성 시각

## 5. 날짜 처리

- 날짜는 한국 표준시(Asia/Seoul)를 기준으로 변환한다.
- 출력 형식은 `YYYY-MM-DD`로 한다.
- 시, 분, 초는 Markdown에 기록하지 않는다.
- 한꺼번에 작성된 묶음이 날짜를 넘어간 경우 각 부분의 실제 날짜는 내부 검증 파일에 보존하되, Markdown 표시는 구현 검증 후 가장 자연스러운 실제 게시 날짜를 사용한다.

## 6. 정렬과 파일 구성

- 오래된 게시물부터 최신 게시물 순서로 정렬한다.
- 계정 하나당 Markdown 파일 하나를 만든다.
- 연도별 또는 월별로 자동 분할하지 않는다.
- 권장 결과 구조는 다음과 같다.

```text
output/
└─ account_name/
   ├─ account_name.md
   ├─ collection-state.json
   └─ collection-report.json
```

## 7. Markdown 출력 형식

- 서로 다른 논리적 게시물 사이에는 Markdown 수평선 `---`를 한 줄 넣는다.
- 수평선 앞뒤에는 빈 줄을 둔다.
- 같은 날짜에 여러 게시물이 있어도 게시물마다 날짜 제목을 다시 쓴다.
- 별개 게시물을 설명하기 위한 임의의 문장은 삽입하지 않는다.
- `################` 같은 비표준 구분선은 사용하지 않는다.
- 원문에 Markdown 문법으로 해석될 수 있는 문자가 있더라도 본문이 손상되지 않게 처리한다.

예시:

```markdown
# @account_name Threads 보관본

## 2025-03-21

### 1/3

첫 번째 본문입니다.

### 2/3

두 번째 본문입니다.

### 3/3

세 번째 본문입니다.

---

## 2025-03-22

**리포스트**

리포스트된 원글 본문입니다.

---

## 2025-03-22

다음 게시물의 본문입니다.
```

위 예시의 `1/3` 등의 표시는 Threads에서 실제 순서를 확인할 수 있을 때만 출력한다. 순서를 확인할 수 없는 묶음의 각 부분은 번호를 만들지 않고 `### 이어지는 글`로만 구분한다.

## 8. 실행 방식

- 비전문가가 사용할 수 있는 Windows용 작은 데스크톱 프로그램을 목표로 한다.
- 사용자는 프로그램을 더블클릭하여 실행할 수 있어야 한다.
- 로컬 웹 서버 방식은 사용하지 않는다.
- 최소 화면 요소:
  - Threads 계정명 입력란
  - 결과 폴더 선택
  - 수집 시작 버튼
  - 현재 진행 상태
  - 발견한 게시물 수와 저장한 게시물 수
  - 중지 버튼
  - 최종 결과 상태
- 브라우저 접근이 필요하면 작업 과정을 확인할 수 있는 전용 Chrome 창을 사용한다.
- 사용자의 평소 Chrome 프로필이나 쿠키를 몰래 읽거나 복사하지 않는다.

## 9. 로그인 정책

1. 공개 페이지를 로그인 없이 먼저 수집한다.
2. 끝까지 접근할 수 없거나 누락 가능성이 감지되면 자동 로그인을 시도하지 않고 멈춘다.
3. 프로그램은 로그인 필요 사실과 중단 이유를 사용자에게 보여준다.
4. 사용자가 계속하기로 선택한 경우에만 전용 Chrome 창에서 사용자가 직접 로그인한다.
5. 비밀번호, 세션 쿠키 또는 인증 정보를 결과 폴더에 저장하지 않는다.

## 10. 계정 안전과 요청 정책

- 한 번에 계정 하나만 수집하며 병렬 수집하지 않는다.
- 요청은 순차적으로 처리한다.
- 서비스 제한 응답이나 일시 오류가 발생하면 간격을 늘려 재시도한다.
- 로그인 확인, 보안 확인, CAPTCHA, 접근 제한 또는 반복 오류가 나타나면 즉시 자동 수집을 중단한다.
- 보안 확인을 우회하는 기능을 만들지 않는다.
- 이미 확인한 페이지나 게시물을 불필요하게 반복 요청하지 않는다.
- 사용자는 하루나 이틀에 계정 하나 정도로 나누어 실행할 수 있다.
- 계정 정지 위험을 완전히 없앨 수 있다고 표시하거나 보장하면 안 된다.

## 11. 누락 검증과 이어받기

- 사용자용 Markdown과 별도로 내부 검증 파일을 저장한다.
- `collection-state.json`에는 최소한 다음 내용을 기록한다.
  - 대상 계정명
  - 수집 시작 위치와 마지막 확인 위치
  - 발견한 게시물의 내부 식별자
  - 처리 완료 여부
  - 중복 제거 상태
  - 중단 후 이어받기에 필요한 정보
- `collection-report.json`에는 최소한 다음 내용을 기록한다.
  - 실행 시작일과 종료일
  - 발견한 항목 수
  - Markdown에 저장한 항목 수
  - 텍스트가 없어 제외한 항목 수
  - 답글이라 제외한 항목 수
  - 중복 항목 수
  - 실패한 항목과 실패 이유
  - 최종 상태: `완료`, `불완전`, `중단`
- 내부 식별자와 원본 위치 정보는 검증 파일에만 둘 수 있으며 사용자용 Markdown에는 표시하지 않는다.
- 동일 게시물이 중복 노출되어도 Markdown에는 한 번만 기록한다.

## 12. 실패 처리

- 실패를 조용히 무시하지 않는다.
- 일부 게시물 또는 묶음의 수집이 실패하면 전체 결과를 `불완전`으로 표시한다.
- 논리적 게시물의 일부만 확인된 경우 Markdown의 해당 위치에 다음 경고를 남긴다.

```text
[수집 실패: 이 게시물의 일부 내용을 확인하지 못함]
```

- 실패 원인과 내부 식별자는 `collection-report.json`에 자세히 기록한다.
- 중간에 프로그램이 종료되어도 이미 확인한 진행 상태를 이용해 이어서 실행할 수 있어야 한다.

## 13. 이번 버전에서 제외하는 기능

- 여러 계정 동시 수집
- 예약 또는 주기적 자동 실행
- 새 글 자동 추가
- 삭제 또는 수정 감시
- 기간 지정 수집
- Google Drive, Dropbox 또는 Git 자동 백업
- 미디어 다운로드
- 로컬 웹 관리 화면

기간 지정 수집 등은 향후 기능으로 추가할 수 있지만 현재 구현 범위에는 포함하지 않는다.

## 14. 완료 판정 기준

다음 조건을 모두 충족해야 해당 계정 수집을 `완료`로 판정한다.

- 공개 프로필의 접근 가능한 게시물 목록을 끝까지 탐색했다.
- 모든 발견 항목이 저장, 규칙에 따른 제외 또는 명시적 실패 중 하나로 분류되었다.
- 중복 제거가 완료되었다.
- 한꺼번에 작성된 게시물 묶음이 가능한 범위에서 온전히 결합되었다.
- Markdown이 오래된 날짜부터 정렬되었다.
- Markdown과 검증 보고서가 정상적으로 저장되었다.
- 해결되지 않은 접근 제한이나 누락 의심 항목이 없다.

삭제된 게시물, 지역·연령 제한 게시물, 실행 당시 사용자에게 보이지 않는 게시물, Threads가 목록에 제공하지 않는 게시물까지 완전성을 보장하지는 않는다.

## 15. 구현 전 필수 검증 항목

- Threads가 작성 시 한꺼번에 만든 묶음과 나중에 추가한 자기 답글을 어떤 데이터로 구별하는지 확인한다.
- 공개 프로필 게시물 목록이 가장 오래된 글까지 페이지 이동되는지 확인한다.
- 단순 리포스트의 본문과 리포스트 시점을 안정적으로 얻을 수 있는지 확인한다.
- 긴 텍스트 첨부물의 전문을 얻을 수 있는지 확인한다.
- 로그인하지 않은 상태와 로그인한 상태의 수집 범위 차이를 확인한다.
- 공식 Threads API만으로 요구사항을 충족할 수 있는지 먼저 확인하고, 부족한 부분만 보이는 Chrome 자동화로 보완한다.
