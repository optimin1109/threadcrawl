# Chrome 확장 0.4.6 검증

통합 시험과 로컬 읽기 화면 검증을 완료했다. 설치 파일 적용과 Chrome 재로드 후 실제 재수집은 별도 단계다.

## 사용자 자료에서 확인한 문제

사용자는 0.4.5의 미완료 글 재수집 후 21묶음 중 4묶음만 보완됐고, 저장된 글이 1,305개인데도 일반 계속하기가 여전히 느리다고 보고했다. 로컬 내보내기 두 파일을 읽기 전용으로 비교한 결과는 다음과 같다.

- 이전 자료는 1,282개·미완료 21묶음, 이후 자료는 1,305개·미완료 17묶음이다.
- 남은 17묶음의 미확보 번호는 총 20개이며, 해당 게시물 ID는 모두 카드 기록에 있다. 번호 관계 충돌이 원인은 아니었다.
- 20개 중 13개는 과거 본문·번호가 모두 `null`인 판독 실패 기록, 4개는 순번 표식 경고, 3개는 본문 뒤 첨부 구조 경고였다.
- 전체 1,305개 중 본문이 `null`인 카드는 316개, 카드에 경고가 있는 기록은 325개였다. 두 수는 중복될 수 있으므로 합산하지 않는다. 저장된 글 개수는 본문을 모두 확보했다는 뜻이 아니다.

사용자 본문과 내보내기 파일은 로컬 진단에만 사용한다. 저장소에는 합성 회귀 자료와 집계·구조 설명만 남긴다.

## 판독과 과거 기록 보완

기존 병합은 과거 본문과 번호가 동시에 `null`이면 이후 정상 본문·번호를 읽어도 최초 기록을 보존하는 경고로 남겼다. 0.4.6은 판독 실패 경고가 있던 미확인 기록을 현재 정상 번호 본문으로 보강한다. 게시물 ID·작성 시각·분류가 같고 기존 첨부를 보존할 때만 허용한다. 확정된 본문의 실제 변경이나 관계 충돌을 지우지 않는다.

실제 제보 페이지에서 확인한 다음 구조를 추가로 처리한다.

- 계정 언급이 서비스 순번과 같은 외부 클래스를 쓰는 경우: 언급 텍스트를 본문에 보존하고, 숫자 순번만 별도로 판독한다.
- 확인된 인라인 동영상: 작성자 본문·번호와 동영상 존재 메모를 남긴다. 영상 파일·음성·자막·CDN 주소는 저장하지 않는다.
- 지구본 대신 사이트 아이콘 이미지가 있는 외부 링크 미리보기: 기존처럼 제목·표시 도메인·안전한 목적 주소를 별도 메모로 보존한다.
- `더 보기` 문구 없이 전체가 표시되는 짧은 텍스트 첨부: 확인된 첨부 링크·단락 구조에서 실제 표시 텍스트를 저장한다.

알 수 없는 조작 요소·중첩 인용·부정확한 번호는 계속 경고한다. 업데이트만으로 저장된 316개 미확인 본문이 채워지지는 않는다. **미완료 글만 다시 수집** 또는 일반 계속하기로 해당 화면을 다시 읽어야 보강되며, 실제 미완료 17묶음의 재수집 결과는 확인 대기다.

## 재개 속도 변경과 한계

실제 reader·storage·content를 연결한 가상 시계 시험에서 세 가지 가속 중단 원인을 재현했다.

1. 2,400px 높이의 저장된 글 안에서 390px씩 실제로 내려가도 DOM이 그대로이면 기존 조건이 매번 1.5초 대기로 돌아갔다.
2. 저장소는 과거 묶음 ID를 누적하지만, 현재 화면에는 그 일부만 나타날 수 있다. 본문이 같아도 전체 누적 값과 현재 부분 값을 정확 비교하면 새 자료로 취급됐다.
3. 저장된 사진 메모가 현재 화면에 없으면, 메모를 보존해 병합하는 경우에도 가속되지 않았다.

변경 후에는 현재 판독 결과를 기존 자료와 병합한 결과로 비교한다. 본문·번호·첨부·메모에 새 정보나 충돌이 없으면 과거 관계와 메모의 누적 보존 때문에 가속이 꺼지지 않는다. 같은 DOM을 유지하는 긴 글은 실제 하향 이동을 확인하고, 검증된 글 한 개의 화면 경계가 현재 보이는 영역 전체를 덮을 때만 짧은 간격을 유지한다.

긴 기존 글에서 네 번 이동하는 합성 시험은 `1000 → 2500 → 4000 → 5500ms`에서 `1000 → 1500 → 2000 → 2500ms`로 바뀌었다. 첫 이동 이후 세 대기가 4.5초에서 1.5초로 줄었다는 뜻이며, 사용자의 실제 재개 시간이 3분의 1이 됐다는 실측은 아니다.

다음 경계는 유지한다.

- 저장 확인을 기다리고, 화면 높이 65%씩 겹쳐 이동한다. 목록을 임의 위치로 건너뛰지 않는다.
- 새 글·바뀐 본문·새 메모·로딩·미확인 본문·미완료 후보가 있으면 기본 1.5초 간격을 사용한다.
- 실제 위치가 멈췄거나 검증된 글 아래 빈 공간에 도달하면 기본 간격으로 돌아간다. 같은 DOM에서 여러 짧은 글에 걸친 화면도 긴 글 한 개가 전체를 덮는 조건을 충족하지 않으면 기본 간격이다.
- 현재 자료에는 경고 카드가 325개 있다. 화면에 경고 카드가 하나라도 있으면 그 화면의 가속이 꺼지므로, 이미 저장한 1,305개를 모두 빠르게 지나간다고 보장할 수 없다. 수정된 판독·병합으로 정상 보강될 때까지 이 제한이 남는다.
- Threads의 로딩 시간, 상세 방문, 계정 전체 범위의 끝 확인은 별개다. 45분 또는 1,800회 상한은 유지한다. 정상 긴 글 안에서 실제로 내려가는 중에는 30초 무변화 대기를 갱신한다. 위치 정체나 글 아래 빈 공간에서는 갱신하지 않는다. 30,000px 합성 카드로 진행 중 조기 중단과 정체 시 종료를 구분해 검증했다.

## 읽기용 HTML

팝업에 **편하게 읽기 (HTML)**를 추가한다. 기존 JSON v2·Markdown 내보내기는 유지한다. HTML은 본문과 긴 첨부를 일반 문단으로 읽는 한 열 문서이며, 검증된 묶음 관계에 한해서 번호순으로 이어 표시한다.

누락 번호는 해당 위치에 표시하고, 소속이 확인되지 않거나 충돌하는 글은 독립 항목으로 보존한다. 자료 안의 카드 하나를 두 묶음에 중복 배정하거나 버리지 않는다. 원문 공백·줄바꿈과 긴 첨부를 보존하고, 본문 미확보와 빈 텍스트를 구분한다. 외부 이미지·영상·기사 전문을 자동으로 가져오지 않는다.

제공된 1,305개 자료로 생성한 로컬 문서에서는 검증된 관계로 233묶음을 구성했고, 전체 1,305개 카드가 각 한 번씩 남는 것을 확인했다. 이는 문서의 보존·배치 검증이며 1,305개 본문의 확보 또는 전체 계정 수집 완료를 의미하지 않는다. 이 결과는 기존 자료를 다시 읽기 쉽게 만든 것이며 원본 JSON을 수정한 결과가 아니다.

## 검증 상태

- 가속 관련 세 개 회귀는 수정 전 실패를 확인했다. 긴 글의 실제 위치 이동, 정체·하단 공백·경계, 부분 묶음, 메모 보존, 실제 신규·변경 본문, 새 메모와 저장 응답 대기를 구분해 검사한다.
- 과거 미확인 기록 복구는 실제 저장소 병합과 연속글 완료 판정을 연결해 검사한다. 날짜·분류·본문·첨부 충돌 보존도 검사한다.
- 판독은 관측된 언급·동영상·사이트 아이콘·짧은 첨부와 유사하지만 지원하지 않는 구조를 함께 검사한다.
- HTML은 모든 카드의 정확히 한 번 보존, 누락·충돌·관계 미확인, 원문·긴 첨부 보존, HTML 문자 이스케이프와 외부 자원 미사용을 검사한다.
- `npm test`: **210/210 통과**, 실패·생략 0.
- `npm run test:extension`: **184/184 통과**. 전체 시험의 부분집합이다.
- JS/MJS 9개 구문 검사 및 `git diff --check` 통과.
- 독립 검토에서 긴 글 내 진행 중 30초 종료를 재현해 보완했고 관련 50/50 시험을 통과했다. 실제 자료의 HTML 1,305개 카드·긴 첨부 8개 보존 및 완료 표시 218묶음 일치도 별도로 확인했다.
- Chrome의 로컬 HTML에서 연속글 카드·본문 폭·번호 구분을 화면으로 확인했다. 원격 PR/Checks는 로컬 검사 결과와 구분한다.

## 패키지·설치·실행 상태

- 소스·0.4.6 배포 폴더·ZIP 압축 해제본의 12개 파일별 SHA-256이 일치했다. ZIP SHA-256은 `D27EC6C28CB50D915B65948CCF3F0B1251FDFBF35A3B4EFD0016AAABFCF7C53D`이며 로컬 `deliverables/threads-text-archive-0.4.6-sha256.json`에도 기록했다.
- 기존 설치 폴더는 현재 0.4.5다. 수집 중지 상태 확인을 요청했으며, 응답 전에는 실행 중인 파일을 교체하지 않는다.
- Chrome 확장 재로드·Threads 탭 새로고침·실제 미완료 재수집과 일반 재개 시간 확인: **검증 대기**.

시험·문서 생성·패키지 준비와 설치된 Chrome의 실제 수집 성공은 구분한다. 기존 자료 초기화는 수정본 적용에 필요하지 않다. 자료를 보존한 채 코드만 같은 설치 경로에 적용하고, 적용 상태가 확인되면 이 문서를 갱신한다.
