# Chrome 확장 0.4.3: 프로필 연속글 재탐색 방지

## 원인과 수정

사용자는 0.4.2에서 프로필에 보이는 두 편 연속글이 상세에 들어가 정체되는 증상을 보고했다. 대상 계정은 확인했으나 정확한 중단 글은 특정하지 못했다.

현재 실제 프로필과 상세에서 여러 장 사진이 `/media` 링크 대신 `div[role=button][tabindex=0]` 안의 `picture > img`로 표시되는 구조를 확인했다. 사진 사이의 파노라마 보조 버튼은 본문·자식 요소가 없는 네이티브 버튼이다. 기존 판독기는 이를 미확인 첨부로 처리해 번호가 모두 표시되어도 완료하지 못했다. 0.4.3은 확인된 구조만 현재 글의 이미지 note로 기록한다. 알 수 없는 버튼·본문·링크·영상·중첩 게시물은 계속 경고하며 이미지 원본이나 OCR을 저장하지 않는다.

프로필의 불완전 후보를 곧바로 여는 동작도 수정했다. 후보 메타데이터의 저장 확인을 받은 뒤 프로필을 한 번 스크롤하고, 실제 스크롤 시점부터 기본 1.5초 후 다시 판정한다. 같은 명시적 묶음에서 모든 본문이 확인되면 상세를 열지 않는다. 완료 저장 중 DOM이 바뀌더라도 이전 상세 대기를 즉시 제거한다. 원래 링크가 사라진 경우에는 불완전 기록을 남기고 다음 글로 진행한다. 번호 관계를 인접 순서로 추측하지 않는다.

## 검증

- `npm test`: 127/127 통과, 실패·생략 0.
- `npm run test:extension`: 101/101 통과, 전체 시험의 부분집합.
- JS/MJS 8개 구문 검사 및 `git diff --check`: 통과.
- 실패를 먼저 확인한 회귀시험: 사진 버튼 판독, 지연 표시되는 2/2, 스크롤 중 원글 제거, 미완료 메타데이터 선저장, 스크롤 이후 렌더링 여유, 완료 응답 중 DOM 변경.
- 사진 버튼을 포함한 2편 묶음이 프로필에서 완료되고 상세 진입 없이 다음 묶음으로 진행하는 통합시험 통과.
- 실제 다섯 장 사진 구조에 수정 조건을 읽기 전용으로 대조해 일치 확인. 이는 조건 대조이며 설치 확장 실행이나 실제 저장 성공 검증은 아니다.
- 독립 검토에서 발견한 저장 완료와 DOM 변경의 순서 문제, 대기 기록 선저장, 스크롤 이전에 렌더링 여유가 소진되는 문제를 보완했다.

## 배포와 남은 확인

기존 설치 경로 `deliverables/threads-text-archive-0.3.0`을 백업한 뒤 0.4.3 파일로 갱신했다. 소스·배포본·ZIP 압축 해제본·기존 설치 경로의 11개 파일 SHA-256이 일치했다. ZIP SHA-256은 `09DD3BFB17C7050C42E6B4CE4827DCD844B34B279DA5FD34828CB9EDE781E496`이다. 로컬 보고서는 `deliverables/threads-text-archive-0.4.3-sha256.json`, 백업은 `backups/chrome-extension-before-0.4.3/`에 보존했다. 설치 경로를 유지했으며 확장을 재설치하지 않았다.

Chrome 확장 관리 페이지는 브라우저 URL 정책으로 도구 접근이 차단되었다. 사용자가 기존 확장을 새로고침하고 Threads 탭도 새로고침한 뒤 다시 수집하는 확인이 남아 있다. 확장을 삭제하거나 다른 폴더로 재설치하지 않는다. 기존 DB와 권한은 변경하지 않았다.

한 번의 프로필 확인 뒤에도 늦게 나타나는 글, 숨겨진 답글, 지원하지 않는 구조의 완전 수집은 보장하지 않는다. 상세 대기 목록 자체는 현재 실행에만 유지되며 중지·복구 이후 자동 재시도는 보장하지 않는다. 미완료 묶음 기록과 확정한 게시물은 저장된다. 기존 저장 응답의 무기한 지연 가능성은 이번 변경 범위 밖이다. 정확한 제보 글의 재현과 설치 확장의 시작·저장·복귀·다운로드는 미검증이다.
