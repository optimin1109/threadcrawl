# Chrome 확장 0.4.1: 2편 글 상세 정체 수정

## 재현한 문제

사용자는 0.4.0에서 목록에 1/2·2/2가 모두 보이는 사진 포함 글에 진입한 뒤 진행이 멈춰 직접 중지했다고 보고했다.

실제 공개 프로필의 [첫 글](https://www.threads.com/@jingammmm/post/DdX8g5BCWCa)과 [두 번째 글](https://www.threads.com/@jingammmm/post/DdX8g3eCTFT)을 DOM으로 확인했다. 두 카드의 groupIds는 이 두 게시물만 담은 같은 집합이었다. 기존 reader는 텍스트 31자·98자를 읽었지만 첫 글의 사진과 장소 태그를 각각 `첨부/설문/본문 뒤 구조 미검증`으로 기록했다. 그 결과 첫 글이 번호별 본문 완료 판정에서 빠졌다. 기존 candidates는 목록에서 모두 읽었는지 검사하지 않고 모든 1/n을 상세로 열었다.

별도 합성 재현에서는 저장 응답 대기 중 DOM이 계속 바뀌면 dirty 분기가 번호 확인과 30초 복귀 조건을 건너뛰었다. 33,750ms·450회 화면 저장 후에도 상세에 남았다. 매번 문구가 바뀌는 답글 펼치기 버튼도 같은 시간에 450회 클릭되어 간격과 복귀 검사를 건너뛰었다. 조용한 DOM에서는 미지원 사진만으로 무기한 정체되지는 않았으므로 실제 사용자 정체의 단일 원인을 확정하지 않는다.

## 수정 범위

- 실제 확인한 같은 게시물 사진 링크와 장소 태그를 본문 오류에서 분리한다. 사진 바이트·OCR은 수집하지 않으며 JSON notes와 Markdown에 제외 사실·원문 링크를 보존한다. 장소 텍스트도 별도로 남긴다. 다른 게시물 이미지·이미지와 혼합된 미확인 텍스트·알 수 없는 첨부는 여전히 실패로 표시한다.
- 현재 프로필의 같은 groupIds 집합에서 모든 번호의 오류 없는 본문이 확인되면 목록에서 완료한다. 단순 인접·다른 작성자·다른 분모·번호 충돌로 완료하지 않는다. 부족한 번호가 있으면 상세로 진행한다.
- 상세 번호 진전이 30초 없으면 미완료로 복귀하고, 상세 탐색 자체에도 120초 상한을 둔다. DOM 변화·답글 펼치기·목록 로딩이 이 검사를 건너뛰지 못하게 한다. 펼치기 동작 사이에는 기존 탐색 간격을 유지한다.
- DB 이름·스키마·권한은 0.4.0 그대로다. 기존 자료를 삭제하지 않는다.
- 완료 판정은 화면에서 읽은 값만이 아니라 병합 후 실제 저장된 순번·본문·오류를 기준으로 다시 검사한다. 저장 응답에서 미완료로 보정되면 수집기도 그 상태를 사용한다. 기존 순번이 비어 있고 본문·날짜·분류·첨부가 보존되는 경우에만 순번을 보강한다.

## 확인 범위

수정된 reader와 같은 판독 로직을 실제 문제 프로필에서 읽기 전용으로 실행했다. 1/2·2/2 모두 본문 오류가 0개이며, 이미지 링크와 장소 태그만 별도로 남았다. 서비스 순번을 제외한 표시 문단과 본문 두 개가 공백·줄바꿈까지 일치했다. 작성자의 전문과 이미지는 저장소에 포함하지 않았다.

최종 코드에서 `npm test` 116/116, `npm run test:extension` 90/90 통과(후자는 전체 시험의 부분집합). 실패·생략은 0개다. JS/MJS 8개 구문 검사와 `git diff --check`도 통과했다. 설치된 0.4.1을 다시 로드한 실제 자동 수집 검증은 별도로 필요하다. Chrome 확장 관리 화면은 도구 URL 정책상 접근할 수 없어 사용자가 새로고침해야 한다.

독립 리뷰에서 기존 저장 카드의 순번이 비어 있거나 충돌하는 경우 팝업 완료 수와 Markdown 검증이 다를 수 있음을 재현했다. 저장소의 완료 검증, 안전한 빈 순번 보강, 저장 응답을 수집기에 반영하는 회귀 시험으로 보완했다. 상세로 다시 확인한 글이 "목록에서만 확보"로 잘못 표기되지 않도록 출처도 갱신한다.

이전 버전이 이미 완료로 저장한 기록은 계정별 첫 접근에서 실제 저장 카드로 재검증하며, 완료·불완전 카운터도 같은 트랜잭션에서 바로잡는다. 비어 있지 않은 기존 순번이 충돌하면 원문을 덮어쓰지 않고 불완전으로 남긴다. 기존 DB를 직접 구성한 재시작·조회·내보내기 회귀 시험이 통과했다. 계정 메타에 검증 규칙 버전을 남겨 반복 팝업 조회마다 전체를 재검사하지 않는다.

## 배포와 복구

기존 설치 경로 `deliverables/threads-text-archive-0.3.0`를 유지해 파일을 갱신한다. 확장을 삭제하거나 다른 경로에 다시 설치하지 않는다. 이전 0.4.0 설치 파일 11개를 백업·압축 해제하고 SHA-256 일치를 확인했다. 0.4.1은 같은 DB 스키마 2를 쓰므로 문제 시 수집 중지·자료 내보내기 후 0.4.0 파일 백업으로 복원하고 재로드할 수 있다.

최종 0.4.1 소스·ZIP 압축 해제본·기존 설치 폴더의 11개 파일 SHA-256이 모두 일치했다. 로컬 패키지는 `deliverables/threads-text-archive-0.4.1.zip`, 검증 보고서는 `deliverables/threads-text-archive-0.4.1-sha256.json`이다. ZIP SHA-256: `4D70F12ECBC60F908FDDFB20D6BC0145DB008C9212480EEEF209682C4D4C0DF9`.

기존 [초안 PR #2](https://github.com/optimin1109/threadcrawl/pull/2)를 갱신한다. 원격 CI는 구성되어 있지 않으며, 설치 후 실행 검증이 남아 있어 초안 상태를 유지한다. 원본 `threads-archive-requirements/`의 미커밋 상태 46개는 이동 당시 기록과 동일하다.
