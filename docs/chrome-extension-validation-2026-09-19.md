# Chrome 확장 0.3.0 검증 기록

## 결과

외부 수집기의 긴 첨부 누락을 해결하기 위해 현재 로그인된 Chrome 프로필 DOM을 읽는 확장을 보완했다. 기존 reader는 본문 컨테이너 첫 자식의 66자 소개글만 읽고, 형제 요소에 있는 긴 첨부를 미지원 처리했다.

실제 공개 프로필 표본 `https://www.threads.com/@hongso0921/post/DOXZaAqkQlt`에서 소개글 66자, 첨부 7,835 Unicode code points, LF 62개를 읽었다. 첨부 전문은 별도로 펼쳐 확인한 원문 문자열과 정확히 일치했다. 작성자의 전문은 저장소에 포함하지 않았다.

프로필 첫 화면에서 원글·후속글 5개를 읽었다. `2/3` 후속글은 본문 컨테이너의 한 클래스가 달랐으며 실제 DOM을 확인해 별도 지원했다. 다음 화면의 추가 2개는 인용/중첩 및 미지원 본문 구조라 명시적 경고로 남겼다. `3/3`처럼 추가 답글 열기 뒤에 있는 글까지 자동 수집했다는 증거는 없다. 이 표본은 전체 이력 수집이나 모든 유형 지원을 증명하지 않는다.

## 로컬 검증

- `npm test`: 56개 통과, 실패/생략 0. 기존 코어 26개와 확장 시험 30개.
- reader와 스크롤은 jsdom, IndexedDB는 fake-indexeddb로 검증한다. 실서비스 접근이나 유료 API 호출을 자동 시험에 사용하지 않는다.
- 원본 저장소의 미커밋 변경은 별도 작업 트리로 격리했다. 기존 확장 7개 파일은 ZIP 압축 해제 후 원본 SHA-256 일치를 확인했다.
- 독립 리뷰에서 숨은 팝업 오탐, 계속되는 DOM 변화에 의한 시간 상한 누락을 발견하고 회귀 시험과 함께 수정했다.
- 설치에 필요한 실행 파일은 manifest/reader/content/background/capture/storage/export/popup HTML/popup JS 9개이며 외부 실행 의존성이 없다.

## 아직 확인되지 않은 부분

브라우저 도구의 URL 보안 정책이 `chrome://extensions/` 접근을 거부했다. 제한을 우회하지 않았으며, 사용자가 압축해제 확장을 로드하는 단계가 필요하다. 따라서 실제 설치 후 시작·중지·Chrome 다운로드의 전체 연결 검증은 미완료다. 로컬 모듈 시험과 실제 DOM 읽기 결과를 설치 완료로 표현하지 않는다.

필요한 후속 확인: README대로 설치한 뒤 대상 프로필에서 시작, 글 수 증가 확인, 중지, JSON/Markdown 저장. 긴 첨부 마지막 문장과 7,835자 보존, 새로고침 후 기존 글 수 유지 확인. 과거 도달 범위는 고정 글을 제외하고 별도로 측정한다.

## 배포 범위

브랜치 `codex/chrome-long-text-archive-2026-09-19`의 [초안 PR #2](https://github.com/optimin1109/threadcrawl/pull/2)로 제공한다. 구현 커밋은 `535b99d`이며 배포 기록은 후속 문서 커밋으로 보완한다. 병합·스토어 게시·운영 배포는 포함하지 않는다. 새 DB 이름을 사용하므로 기존 실험판 자료와 분리되며 롤백은 새 확장을 비활성화하고 검증된 이전 파일을 복구한다.
