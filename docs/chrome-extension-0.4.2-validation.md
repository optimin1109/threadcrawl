# Chrome 확장 0.4.2: 사진만 있는 2/2의 상세 진입 방지

## 원인과 수정

사용자가 제보한 화면은 같은 프로필 묶음에 글과 사진이 있는 `1/2`, 사진만 있는 `2/2`가 모두 표시된다. 기존 판독기는 캡션 컨테이너가 없는 후속 편을 미확인 구조로 남겼다. 따라서 묶음을 완료하지 못하고 이미 보이는 글의 상세를 열었다.

0.4.2는 번호 표식, 같은 작성자·묶음, 같은 게시물의 `/media` 링크, 텍스트가 섞이지 않은 이미지 구조를 모두 확인한 경우에만 빈 본문의 미디어 전용 편으로 기록한다. 여러 장의 사진도 이미지 note 하나로 표시하며 이미지 바이트와 OCR은 저장하지 않는다. 다른 게시물 링크나 미확인 텍스트·버튼은 계속 오류로 남긴다.

프로필에서 모든 번호를 확인하면 상세를 열지 않는다. 실제로 번호가 빠져 상세에 들어간 경우에는 번호 진전이 없는 대기를 30초에서 10초로 줄였고, 전체 상세 탐색 상한 120초는 유지했다.

## 검증 범위

실패 시험에서 미디어 전용 `2/2`의 순번은 `null`이었고 프로필 묶음은 상세로 진입했다. 수정 후 판독 시험은 `2/2`, 빈 본문, 이미지 note, 오류 없음으로 통과했다. 묶음 통합 시험은 `1/2` 글·사진과 `2/2` 사진만을 같은 그룹에 두고 완료 상태 저장, 상세 진입 없음, 다음 묶음 진행을 확인한다.

`npm test` 118/118, `npm run test:extension` 92/92가 통과했으며 실패·생략은 0개다. JS/MJS 8개 구문 검사와 `git diff --check`도 통과했다.

기존 설치 폴더 `deliverables/threads-text-archive-0.3.0`을 0.4.2로 갱신했다. 소스·ZIP 압축 해제본·설치본 11개 파일의 SHA-256이 일치한다. 배포 ZIP은 `deliverables/threads-text-archive-0.4.2.zip`, 검증 보고서는 `deliverables/threads-text-archive-0.4.2-sha256.json`, ZIP SHA-256은 `5A297748CFB3A25A637D7165C93CC8B6E6DAEA3A245E9DEDB829EA44A27305FD`다. 이전 0.4.1 설치본은 `backups/chrome-extension-before-0.4.2/`에 보존하고 파일 해시를 확인했다.

설치된 0.4.2의 실제 자동 수집은 Chrome 확장과 Threads 탭을 사용자가 새로고침한 뒤 별도로 확인해야 한다. 확장을 삭제하거나 다른 폴더에서 다시 설치하지 않는다.
